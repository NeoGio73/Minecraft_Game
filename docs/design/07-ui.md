Owner: WP-09 (files in `src/ui/*`, `src/app/Settings.ts`). WP-11 wires `Game.ts`/`State.ts` to the interfaces in §1. Precedence: `docs/SCOPE.md` > `00-contracts.md` > this document > research reports (acids-bases-hybrid §3.4, §6, §7; reaction-bench §4.3, §4.4; stereo-on-grid §1.5, §6, §8, §9; d2l-hosting recommendations) > DESIGN-draft §2.4, §3, §7.

`setChallenge` semantics the UI relies on: (1) previous locked molecules are removed without inventory change; (2) for `select-atom` the rule's molecules are placed at `LOCKED_ORIGINS[i]` using `layoutOf(entry)` (05 §1) translated so its min corner is the origin, explicit H blocks placed for every `hPos`; bond orders and charges written into `MoleculeIndex`; locked cells refuse mining, bonding and charging with `REFUSAL_TEXT.lockedZone` — the string is reused verbatim (unresolved item 3); (3) for `quiz` rules with `display`, the molecule is placed at `LOCKED_ORIGINS[0]` and `hooks.setMarkedAtom` receives the marked atom's cell; (4) for bench rules 04 §8.2 applies; (5) `selection` is cleared and `selection:changed` emitted; (6) `target:changed` is emitted for the first locked component so the molecule panel describes it.

Tab order = DOM order: skip link → toolbar → challenge panel → canvas → molecule panel → bench panel → hotbar. `#target-info` and `#look-hint` are visual only; their content reaches screen readers through the status region on Analyze (§16). Every dialog is a child of `#dialogs` with `role="dialog" aria-modal="true"`; while one is open, `#hud` and `#canvas` get the `inert` attribute — `#toast`, `#status` and `#scene-mirror` never do (§17), so announcements made from a dialog (quiz feedback, `lms:committed` after Save & Exit, the finished overlay, settings changes, refusals while a confirm is up) are still spoken (WCAG 4.1.3). `#toast` is visually positioned over the HUD (§16.1) even though it is not a child of `#hud`.

`role="application"` on `#canvas` (and only there — the HUD panels and dialogs stay in browse/virtual mode): NVDA and JAWS switch to focus/forms mode when the canvas receives focus, so the arrow keys, single letters (W A S D, F, H, L, R, T, digits, `[` `]`) and Space reach the game's `keydown` handler instead of being consumed as screen-reader navigation; Tab still leaves the canvas. The `aria-label` names the keys that matter before the learner can read Help. `#stage` never gets `role="application"`.

### 2.2 Stage sizing (00-contracts R16)

```css
html, body { margin: 0; overflow: hidden; background: var(--bg); }
#stage { position: relative; width: 100%; }
#stage[data-framed="true"]  { height: 100vh; }                       /* the iframe's own height */
#stage[data-framed="false"] { height: 100dvh; }
#stage:fullscreen { width: 100%; height: 100%; }
#canvas { position: absolute; inset: 0; width: 100%; height: 100%; display: block; }
#hud > * { position: absolute; }
#toast, #status, #scene-mirror { position: absolute; }        /* direct children of #stage (§2.1); #toast is un-hidden over the hotbar for TOAST_MS (§16.1) */
```
`framed = window.self !== window.top`, set once by `main.ts` on `#stage[data-framed]`. The renderer resizes from a `ResizeObserver` on `#stage` (one resize per animation frame). No `aspect-ratio` rule anywhere (the framed 580 px D2L viewer is the binding case; the new-window SCORM player wants the full viewport, which `100dvh` gives without a `min-height` that could overflow a short pop-up).

Decision (one rule for both owners): the stage CSS above is normative; WP-08 ships no `#stage` sizing rule of its own. 00-contracts R16 ("`aspect-ratio` only when top-level"), 06 §11.4 (`aspect-ratio: 16/9; max-height: 100dvh; min-height: 480px`) and 08 §7 (which cites 06 as normative) are to be edited to read `top-level → height: 100dvh` with the `aspect-ratio` sentence removed; until they are, this section wins (00-contracts precedence applies only to the TypeScript contracts, and R16 is a layout note). `#stage:fullscreen` uses `width: 100%; height: 100%` here versus `100vw/100vh` in 06 — identical inside the fullscreen viewport.

Panel geometry (all with 16 px gutters, `max-height: calc(100% - 96px)`, `overflow: auto`): toolbar top 0, height 40; challenge panel left 16 / top 56 / width `min(360px, 40%)`; molecule panel right 16 / top 56 / width `min(380px, 40%)`; bench panel right 16 / bottom 88 / width `min(420px, 45%)` (stacks under the molecule panel; when both are open the molecule panel collapses to its title bar with a "Show" button); hotbar bottom 16 centred; crosshair centre; target-info centre, top `calc(50% + 24px)`; look-hint centre, bottom 96.

`@media (max-width: 899px)`: challenge and molecule panels become tabs in a strip above the hotbar (`role="tablist"`, buttons "Challenge" / "Molecule" / "Bench"); the active tab opens as a sheet `height: 55%` anchored to the bottom; only one sheet at a time. `@media (pointer: coarse)`: `#touch-controls` is shown (D-pad `role="group" aria-label="Move"`, Jump, Mine, Place buttons, each ≥ 44 × 44 px).

`uiScale` sets `font-size` on `#hud` (16 px × scale); nothing in the HUD is below 14 px at scale 1 (hotbar counts) and body text is 16 px.

### 2.3 Theme tokens and contrast

```css
:root {
  --bg: #14171c; --panel: rgba(20, 23, 28, 0.86); --text: #f4f6f8; --muted: #b8c0cc; --border: #c9d1d9;
  --focus: #ffd166; --ok: #7ee787; --err: #ff7b72; --warn: #f0c674; --info: #79c0ff;
  --hover: #ffd54f; --selected: #4dd0e1; --marked: #ff9800;
}
:root[data-theme="light"] {
  --bg: #f6f8fa; --panel: rgba(246, 248, 250, 0.92); --text: #1b1f24; --muted: #4b5563; --border: #57606a;
  --focus: #8a5a00; --ok: #116329; --err: #a40e26; --warn: #7d4e00; --info: #0a53a8;
  --hover: #7d4e00; --selected: #0b6f7e; --marked: #b45309;
}
```
`data-theme` on `<html>` is `dark`/`light` from `Settings.theme`, or from `prefers-color-scheme` when `auto`. Measured contrast (WCAG 2.1 relative luminance) — dark theme on `#14171c`: text 16.6:1, muted 9.8:1, border 11.6:1, focus 12.5:1, ok 11.7:1, err 7.1:1, warn 11.2:1, info 9.2:1, selected 9.8:1, hover 12.7:1. Light theme on `#f6f8fa`: text 15.6:1, muted 7.1:1, border 6.0:1, focus 5.6:1, ok 6.9:1, err 7.4:1, warn 6.7:1, info 7.0:1, selected 5.5:1. Rules: body text ≥ 4.5:1 (all ≥ 5.5), UI component boundaries and focus rings ≥ 3:1 (all ≥ 5.5). The panel backing is at least 86% opaque so the world behind it cannot lower the ratio below 4.5:1 for any world colour (worst case: white sand behind the dark panel gives text 12.9:1). The crosshair is a 2 px white cross with a 1 px black outline (21:1 against each other, so ≥ 3:1 against any backdrop).

Focus ring on DOM controls: `outline: 2px solid var(--focus); outline-offset: 2px` (they sit on a panel background, where the ratios above apply). The canvas is the exception: it is `position: absolute; inset: 0` inside a stage that fills the viewport with `overflow: hidden`, so an outward `outline-offset` would be clipped and invisible (WCAG 2.4.7), and every token above fails 1.4.11 against the sky (`CLEAR_COLOR #9fc5e8`, 06 §11.1): focus `#ffd166` 1.25:1, hover `#ffd54f` 1.28:1, selected `#4dd0e1` 1.02:1, ok `#7ee787` 1.18:1, err `#ff7b72` 1.40:1, marked `#ff9800` 1.19:1. Rule for everything drawn over the 3D world: a two-tone ring, colour next to black, so the pair is ≥ 3:1 against any backdrop (focus yellow on black 14.6:1, black on the sky 11.6:1; the weakest pair, err `#ff7b72` on black, is 8.3:1).

```css
#canvas:focus-visible { outline: 3px solid var(--focus); outline-offset: -3px; box-shadow: inset 0 0 0 5px #000; }
#canvas:focus:not(:focus-visible) { outline: none; box-shadow: none; }
```
(the inset `box-shadow` is the black band under the 3 px yellow inset outline: 3 px yellow, then 2 px black, all inside the viewport). This is the single normative rule for the canvas ring; 06 §11.4's `outline: 2px solid #ffd166; outline-offset: -2px` is to be replaced by it. The 3D select/hover/marked outlines (§11.2), the quiz marked-atom outline (§1.3 `setMarkedAtom`) and the R/S halos of `StereoOverlay` are drawn the same way: a 1 px black inner line plus the 2 px colour line, exactly as the crosshair is.

Colour is never the sole cue: every status colour is paired with a glyph and a word (§9.5, §11.4), stereo labels are text, hotbar selection has a ring and `aria-pressed`, highlight buttons list the highlighted atoms in text.

### 2.4 Reduced motion

`reducedMotionActive(settings)` drives `<html data-reduced-motion="true">` and `hooks.setReducedMotion(true)`. Under reduced motion: no CSS transitions (`* { transition: none !important; animation: none !important }` scoped to `#stage`), no crosshair flash, no pulsing outlines (hover/selected/correct/wrong/marked become static outlines), no head bob or FOV kick (renderer), no fade on toasts (they appear and disappear at their timeouts). Nothing in the game flashes above 3 Hz in either mode: the correct-set pulse (§11.4) is 2 pulses of 600 ms.

Handler policy (`src/input/InputManager.ts`, restated because the HUD depends on it): key handlers live on `window` and act only when `document.activeElement === canvas` or pointer lock is held; in that state `preventDefault()` is called for Space, the arrow keys, PageUp/Down, Home/End and every bound code; never for Tab, Escape, F-keys, or when a DOM input/dialog has focus. The pressed-key set is cleared on canvas `blur`, window `blur` and `visibilitychange`. `contextmenu` is prevented on the canvas; the wheel listener is `{ passive: false }`. Single-letter shortcuts are therefore active only while the canvas has focus (WCAG 2.1.4).

Pointer lock: attempted only in the canvas click handler; on failure the `#look-hint` shows `STRINGS.dragToLook` for 4 s and `look:mode` switches to `drag`. After Escape, no auto-relock; `#look-hint` shows `STRINGS.clickToLook` until the next click.

### 8.2 Refresh algorithm (`refresh()`; dirty on `target:changed`, `molecule:analyzed` for the targeted component, `bond:changed`, `bond:suppressed`, `bond:restored`, `charge:changed`, `settings:changed`)

1. `a = state.target.analysis`. If null: show `.mp-empty`, hide everything else, clear the group highlight, return.
2. Name: `a.name ?? STRINGS.unnamed`. Formula: `a.formula` rendered with digits in `<sub>`; the trailing charge (`+`, `-`, `2-`) rendered in `<sup>`; `aria-label` = plain `a.formula`.
3. Facts: net charge with sign (`+1`, `−1`, `0`); DoU text `STRINGS.dou(a.dou, C, N, H, X)` where `X = F + Cl + Br + I`; size `STRINGS.size(heavy, H, rings, components)` (heavy = `a.atoms.length`, `H = Σ a.hydrogens`); the `No-bond pairs` row is shown only when `state.target.suppressed.length > 0`, with `STRINGS.noBondPairs(n)` followed by `: ` and the pair labels (`C1–C4`, each atom labelled in its own component) joined by `, ` (09 §5.6).
4. Groups: one `<li>` per `a.groups` entry in order, label = `hit.label`; the highlight button's `aria-label` lists `hit.atoms` as atom labels. Empty → `STRINGS.noGroups`. Clicking a highlight button: if it was pressed → `hooks.setGroupHighlight(null)`, `aria-pressed=false`; else un-press every other, `hooks.setGroupHighlight(hit.atoms.map(id => atomToCell[id]))`, `aria-pressed=true`. The highlight is cleared on `target:changed` to a different component.
5. Stereo (only when `a.stereo !== null`): first line `STRINGS.chiralLine(chiral, meso, nCenters)` → `Chiral · 1 chirality center` / `Achiral (meso) · 2 chirality centers` / `Achiral · 0 chirality centers`. Centres: every entry with label ≠ `NOT_CENTER`: `C{n}: {label text}` where label text is `R` / `S` / `unspecified` / `cannot assign`; for R/S append ` — priorities ` + `priorities` joined by ` > ` (atom label or `H`); for `UNSPECIFIED`/`CANNOT_ASSIGN` append the `hint` on a second line. Double bonds: `C{a}=C{b}: {label}` with `label` rendered as `E`/`Z` (+ ` (trans)`/` (cis)` from `cisTrans`), `no E/Z`, `ring`, or the geometry problem word (`collinear`, `not planar`, `twisted`) followed by the `hint`. Ring faces: for each `ringFaces` entry with ≥ 2 substituents whose `face ≠ 0`: `Ring {k}: substituents on C{i} and C{j} are {cis|trans}` (`cis` when both faces equal). Nothing to show → `STRINGS.noStereo`.
6. Acidity: `mostAcidic[0]` → `STRINGS.mostAcidic(label, pKa, verified, source, atomLabel)`; when `verified === false` the number is prefixed `≈` and the source text is `general value, not in McMurry`; when `a.acidity.hydrogens` is empty → `STRINGS.noHydrogens`. `mostBasic[0]` → `STRINGS.mostBasic(atomLabel, label, pKaH, verified)`; none → line hidden. The "All hydrogens" table has one row per distinct `classKey` per parent: atom label, count, class label, pKa (≈ when unverified), source.
7. Atoms: `.mp-targeted-atom` shows the row for `state.target.cell` when it is an atom of this component (`STRINGS.targetedAtom(label, hybridization, geometry, idealAngle)`), else hidden. Table rows in id order: `#` = n, element name, `heavyBondOrderSum`, `hydrogens`, `lonePairs`, charge with sign, `hybridization` (`none` → `—`), `geometry`, `idealAngle` (`null` → `—`), `observedAngleNote ?? ''`. The row for the targeted cell has `class="is-targeted"` and `aria-current="true"`.
8. Warnings: one `<li>` per `a.warnings` entry via `warningText(w, a)` (§19.3), prefixed with the glyph `⚠` and the word `Warning:`. Empty → `STRINGS.noWarnings`. New warning texts (not present in the previous refresh) are also announced politely (§16).
9. Locked components: when `state.padComponents` marks the component `locked`, the title reads `Targeted molecule (locked by the challenge)`.

## 11. Select-atom mode (`select-atom.ts`)

Active while `state.current.challenge.rule.type === 'select-atom'`; entered on `challenge:changed`, exited on the next `challenge:changed`. The hotbar auto-selects slot 12 (select tool); choosing another slot is allowed (the student may build elsewhere on the pad) but Place on a locked molecule always acts as select while the mode is active.

### 11.1 How implicit hydrogens become targetable

1. `hooks.setHydrogenMode('select')` when `rule.target === 'hydrogens'` (mini-blocks at 100% opacity, 0.4 × block, `#F2F2F2`, symbol `H` on each face); `'blocks'` if `Settings.showHydrogens` and `target === 'atoms'`; restored on exit. `T` is ignored while the mode forces `'select'`.
2. Candidate list, built on entry and after `molecule:analyzed` for a locked component (deterministic order = cycling order):

```
candidates = []
for (m, lp) of state.locked (rule.molecules order):
  for atom of 0..lp.atomToCell.length-1:
    cell = lp.atomToCell[atom]; [x,y,z] = parseCellKey(cell)
    if rule.target === 'atoms':
      candidates.push({ molecule: m, atom, cell, center: [x+.5,y+.5,z+.5], half: 0.31 })      // atoms render at 0.62 scale
    else:
      n = lp.analysis.hydrogens[atom]; explicit = lp.hCells.get(atom) ?? []
      for slot of 0..n-1:
        if slot < explicit.length:   c = parseCellKey(explicit[slot]); half = 0.275                // explicit H block, 0.55 scale
        else:                        c = implicitHCell(getBlock, x, y, z, slot - explicit.length); half = 0.2
        if c === null: continue      // no free face (cannot happen for content: validator B3 places every molecule with free faces)
        candidates.push({ molecule: m, atom, hSlot: slot, cell, center: [c0+.5, c1+.5, c2+.5], half })
      if n > 0: heavy.push({ molecule: m, atom, cell, center, half: 0.31 })                     // fallback targets (not cycled)
```
`explicitHCell` slots match `HydrogenSite.slot` ("explicit blocks first, in hPos order", 00-contracts).

3. Picking (each `tick`, every `SELECT_PICK_MS`): `ray = hooks.crosshairRay()`; for every candidate (and heavy fallback) compute the ray/AABB slab intersection with box `center ± half`; keep the smallest `t ∈ (0, PICK_DISTANCE]`. Compare with `hooks.atomHit()` — a heavy-atom hit counts only if its cell belongs to a locked molecule (`lp.cellToAtom.has(cell)`); take the smaller `t`. The winner is `hovered` (null when nothing). A keyboard-cycled candidate (§11.3) overrides `hovered` until the pointer moves ≥ 5 px.

### 11.2 Highlights

`hooks.setSelectHighlights({hovered, selected, correct, wrong})` on every change: hovered = `--hover` outline (yellow, 2 px, pulsing unless reduced motion); selected = `--selected` (cyan) outline plus a floating `selected` sprite; correct = `--ok` green, 2 pulses of `FLASH_MS`; wrong = `--err` red held for `WRONG_HOLD_MS`. Every one of these outlines is two-tone (§2.3): a 1 px black inner line under the 2 px colour line, so the ring stays ≥ 3:1 against the sky, sand and every atom colour. `#target-info` mirrors the hovered candidate in words (§7 rows) so colour is never the sole cue; the scene mirror lists every candidate with its index (§16.3).

### 11.3 Keys

| key | action |
|---|---|
| `[` / `]` | cycle `cycled` through `candidates` (wraps); sets hovered; announces `STRINGS.candidate(i, n, description)` politely, e.g. `Candidate 2 of 6: Hydrogen on O3` |

Heavy fallback on a `'hydrogens'` rule → item without `hSlot` (State's `normalizeSelection` expands it); if the atom has 0 H the toast shows `FEEDBACK['no-hydrogens']()` and nothing is selected |

`selection:changed {cells, hydrogens}` → highlights and `.cp-selection` text in the challenge panel: `Selected: H on O3` / `Selected: C2 (all 3 hydrogens)` / `Selected: C2, C3` / `Nothing selected`.

### 11.4 Result

After `challenge:submitted`: `passed` → `correct = selectedCandidates` (green pulse), selection kept; `wrong-atom` → `wrong = selectedCandidates` for `WRONG_HOLD_MS`, then selection cleared (`state.clearSelection()`); `attempts-exhausted` → `correct = answerSet(rule.selector, graphs, analyses)` mapped to candidates (static green until the challenge changes; the correct set is never revealed before the last attempt), `wrong` as above; `no-hydrogens` → toast only, no attempt consumed. The feedback panel prints the pKa readout for the picked and the correct site when the selector is `most-acidic-h` / `most-basic-*`: `STRINGS.pickedSite(picked label, pKa, source)` and, on pass or exhaustion, `STRINGS.answerSite(label, pKa, source)`; these lines are appended after `result.message`.

Equivalence-class acceptance is content-side (`answerSet` returns every member of the tie class; `itemKey` equality), so the UI treats every candidate uniformly.

### 16.1 Policy

- `polite` → `#status` (`role=status`). Throttled: at most one DOM write per `LIVE_POLITE_MS`; a message arriving inside the window replaces the pending one (latest wins) — except challenge results and quiz results, which are queued FIFO (flag `sticky` set by the callers in §9.4/§10.2). - `#status` and `#toast` are the **only** live regions in the page. `.cp-feedback`, `.mp-warnings`, `.bp-result`, `.quiz-feedback` and the settings key-capture cell are plain regions the learner can read (and the scene mirror copies), never `role=status`/`aria-live`: giving them a live role would make screen-reader users hear every result twice (the panel text and the prefixed announcement) and would bypass the throttle above. `#lms-badge` keeps `role=status` because `lms:status` is not otherwise announced.

## 17. Focus management

- A focus stack in `hud.ts`: `pushDialog(dialog, opener)` stores `opener ?? document.activeElement`, sets `inert` on `#hud`, `#canvas` and on every other open dialog — never on `#toast`, `#status`, `#scene-mirror` or `#dialogs` itself — and focuses `dialog.querySelector('[autofocus]') ?? first focusable ?? dialog` (the dialog element carries `tabindex="-1"` so this last fallback is focusable; the finished overlay, §13.3, has no focusable child); `popDialog()` removes `inert` from the dialog below (or from `#hud`/`#canvas` when the stack empties) and focuses the stored opener (fallback: `#canvas`).
- Focus trap: on `keydown Tab` inside a dialog, compute the focusable list (`button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])`, visible, not disabled); wrap from last to first and first to last; when the list is empty, `preventDefault()` and keep focus on the dialog element. Escape in a dialog → its close (pause menu: resume; quiz: close without answering; confirm: cancel).
- Non-modal panels (challenge, molecule, bench) never steal focus on refresh; DOM updates preserve the focused element when it still exists (rebuild by diffing `data-key` children, not `innerHTML`, for the roster, hotbar and cards).
- The canvas shows the focus ring when focused; `pointerdown` on the canvas focuses it. Tab from the canvas goes to the molecule panel (DOM order) — the game never traps focus (WCAG 2.1.2).
- Pointer lock and focus: opening any dialog calls `document.exitPointerLock()`; closing does not relock.
