# Critic round 1 (critic)

Verdict: **revise**

- **[blocker] 2.6 ScormAdapter — suspend_data / localStorage merge**: The resume rule 'if the LMS returns empty suspend_data but localStorage has a string with more solved bits, use the local copy and re-commit it' is not keyed to the learner. localStorage is per browser profile, not per D2L account. On a shared lab computer (or any second attempt after the instructor resets progress, or after a 'logout' exit starts a new attempt), student B launching the SCO with an empty suspend_data will have student A's bitmask restored and immediately committed as cmi.core.score.raw to B's gradebook entry without B doing anything. This is a grade-integrity defect on the graded path.
  - fix: Read cmi.core.student_id (and cmi.core.lesson_mode) at LMSInitialize; store the mirror under localStorage['orgocraft.v1.progress.<student_id>'] and only merge when the id matches. Never auto-commit a merged score: restore the bitmask into UI state, but write score.raw only when the student next earns a milestone (or require an explicit 'Restore local progress?' confirmation). Add a progress.test.ts case: different student_id → mirror ignored.
- **[major] 5.1 Challenge roster / 2.5 Score model**: 'Total = 45 with all enabled → raw = round(100·earned/45)' is wrong. Counting the table: 7 easy (C01–C04, C08–C10) ×1 = 7, 15 medium ×2 = 30, 3 hard ×4 = 12, total 49. The doc is declared the single source of truth and the number will be copied into tests, INSTRUCTOR.md and the progress bar text.
  - fix: Replace 45 with 49 everywhere (or re-weight to hit a round number), and make challenges.test.ts assert totalPoints from the JSON rather than a literal.
- **[major] 2.6 ScormAdapter — call sequence step 4 (cmi.core.exit)**: Writing cmi.core.exit='logout' as soon as the student has passed (raw ≥ passMark, e.g. 70) tells the LMS the attempt is finished, so the next launch starts a new attempt with empty suspend_data: the student loses their solved set and cannot continue from 70 toward 100 (only the unsafe localStorage mirror papers over this on the same device). 'logout' in SCORM 1.2 also means 'learner logged out of the LMS' and some players act on it. This contradicts 2.5 ('so a student can come back').
  - fix: Always write cmi.core.exit='suspend' unless every enabled challenge is solved; for the all-solved case write '' (normal exit), never 'logout'. Keep lesson_status='passed' with exit='suspend' (valid combination in 1.2; D2L resumes). Add the case to the fake-API test.
- **[major] 1 Goals/Audience and 5.1 — conflict with docs/SCOPE.md**: docs/SCOPE.md (instructor decisions, dated today) says the course is Organic Chemistry I only and lists 'Aromaticity and resonance structures (chapter 15 and beyond)' as explicitly OUT of v1, while stereochemistry (ch 5), E/Z (ch 7), acids/bases & formal charge (ch 2) and the reaction bench (ch 8, 9, 11) are IN. The design does the reverse: 8 of 25 challenges and 20 of 49 points (41% of the grade) are aromatic/Organic II content, the chemistry core is built around aromaticity perception, and every instructor-selected ch 2/5/7(E-Z)/8/9/11 objective has zero coverage. 'This document wins' is asserted unilaterally; for an Orgo I course that disables C18–C25 as suggested, only 17 challenges / 29 points remain and none address the instructor's chosen topics.
  - fix: Make the scope inversion an explicit sign-off item with the instructor rather than a footnote. At minimum: set disabledChallenges default to C18–C25 for the Orgo I course profile, and add Orgo I content the grid can support without stereo — e.g. alkyl halide isomer set C4H9Br (named in SCOPE.md), C6H14 isomer set, 'most acidic hydrogen' quiz panel (SCOPE.md asks for a small quiz panel), name-to-structure alkenes/alkynes. State plainly in section 1 that aromatic content is Organic II and contradicts SCOPE.md.
- **[major] 4.5 Grid geometry facts**: Two stated facts are false. (a) 'The two inside cube vertices touch three ring atoms and are refused by the valence rule' — a carbon placed at (0,1,0) bonds to three ring carbons; in cyclohexane each ring C goes from 2 to 3 bonds and the new C has 3, all ≤ 4, so placement is ALLOWED and silently produces a tri-bridged cage (ring count 3). Only O/halogen placements there are refused. Even in benzene (ring C bond sum 3) the fourth bond is allowed. (b) 'Each ring atom has exactly three outward free faces' is only true in mid-air; on the lab pad the three y=9 ring atoms have their −y face blocked by unbreakable LabTile, leaving two, which makes ortho substitution (aspirin) trickier than described. The Help overlay, the 'unintended chord' warning and molecule-index.test.ts are specified on top of (a).
  - fix: Rewrite 4.5: inner-vertex placement is legal for C/N and produces a cage; add a panel warning 'atom bonded to three ring atoms (cage)' driven by ringCount jump, and a Help note to build rings one block above the floor. Fix the molecule-index test expectation accordingly.
- **[minor] 5.2 / 9.1 — buildability criterion and missing test**: 'Even rings only' is necessary but not sufficient: under auto-bonding a target must be an INDUCED subgraph of the cubic lattice (no non-bonded pair face-adjacent), and nothing in the test plan checks this. I brute-forced an induced embedding for all 96 library entries and all exact/set targets (including naphthalene, aspirin, ibuprofen): all are embeddable, so there is no content bug today, but future additions (e.g. anything with two ortho substituents each branching) can silently become unbuildable.
  - fix: Add test/content/buildable.test.ts: a small backtracking embedder (BFS order, 6 candidate cells per atom, reject if any non-bonded pair becomes adjacent) that must succeed for every library entry and every exact/set target; optionally use the found embedding to drive an end-to-end test through World.setBlock → extract → acceptance so the grid path, not just SMILES, is exercised per challenge.
- **[minor] 2.5 Score model / 2.6 suspend_data codec**: 'failed is written only when every enabled challenge has been attempted' but 'attempted' is not in the suspend_data codec (only solved bitmask, reportedRaw, currentChallengeId), so after any resume the rule cannot be evaluated and failed is effectively never written, or written wrongly from in-memory state.
  - fix: Add an attempted bitmask field to the v1 codec (still far under 100 chars) or drop the 'failed' state and document that only incomplete/passed are ever written.
- **[minor] 5.1 Acceptance types — set challenges**: 'Every component on the lab pad' is undefined: pad membership by x/z range only, or also y? Any/all atoms of a component? A leftover molecule from C03/C04 on the pad rejects C05/C06, and the only specified feedback is 'Stray atom on the pad' (single atoms). Students will not know why a correct pair of butanes is rejected.
  - fix: Define pad = components whose every atom has x,z in [52,76) and y ≥ 9; add feedback 'Extra molecule on the pad: ethanol — remove it' naming the unexpected component; add a 'Clear pad' action in the pause menu that returns atoms to inventory.
- **[minor] 4.8 Functional groups — rule 18 alkene**: SMARTS oracle [CX3]=[CX3] does not match allene double bonds (central carbon is CX2), so for 1,2-butadiene (in the library and accepted by C11) the plain-words rule reports two alkenes while the RDKit oracle reports none; groups.test.ts will fail on it. Related classification gaps: urea/carbamates, N-alkyl anilines and enols receive no group at all; CHCl3/CH2Cl2 are labelled 'methyl halide' by the carbon-neighbour-count rule.
  - fix: Oracle: [#6;X3,X2]=[#6;X3,X2] or document allenes as 'alkene (cumulated)'. Add urea/carbamate, secondary aryl amine (N(H)(C)c) and enol rules, and report polyhalomethanes as 'halomethane'.
- **[minor] 5.1 C12, C13, C15, C16 predicates**: C12 {formula C6H12, ringCountMin 1} is satisfied by 1,1-/1,2-/1,3-dimethylcyclobutane and ethylcyclobutane, all far easier than the chair hexagon the challenge is meant to teach, so the objective is not enforced. C13/C15/C16 restrict only carbon count, so heteroatom-rich molecules (e.g. 1-chloro-3-pentanone, diketones) are accepted; the claim in section 10 that 'each predicate's accepted set is enumerated in challenges.test.ts' is false for open predicates.
  - fix: Add a ringSizes clause (C12: ringSizes includes 6) or make C12 exact C1CCCCC1; add formula clauses to C13 (C5H10O), C15 (C4H10O), C16 (C3H9N) or explicitly document them as open-ended.
- **[minor] 2.6 ScormAdapter — Save & Exit window.close()**: Inside the D2L new-window player the SCO runs in an iframe of the popup; window.opener is null there, so the window.close() branch never runs. If changed to window.top.close() it would close D2L's player before the player's own commit/finish, which is the very 'closing the popup without finishing' problem cited. 'Open in new tab' is also unreachable to the API for the same reason (correctly hidden).
  - fix: Remove window.close(); after LMSFinish show 'Progress saved — use the player's Exit button', or only call top.close() when the top window is same-origin and opened by script.
- **[minor] 2.4 Iframe constraints — stage sizing**: aspect-ratio 16/9 sizing by width can exceed a fixed-height cross-origin iframe (SCORM embedded mode served from the Content Service cannot be auto-resized by D2L): at 1100 px width the stage is 619 px + toolbar in a 580 px frame with overflow hidden, cutting off the hotbar and challenge panel. Inside a frame, 100vh equals the iframe's own height and is the safe choice; the stated 'never 100vh' reasoning only applies to the same-origin auto-resizing viewer.
  - fix: Framed: height: 100vh (fallback min-height 480px only when the frame is same-origin and auto-sized); keep aspect-ratio only for top-level standalone. Verify in checklist 9.3 items 2 and 9.
- **[minor] 6.4 / 6.6 / 4.4 Engine details**: (a) instanceColor via setColorAt is a diffuse multiplier, not an emissive tint, and needs instanceColor.needsUpdate = true. (b) The bond pick mesh rendered with opacity 0 / transparent still costs a draw call and transparent sorting; Raycaster does not check visible, so mesh.visible = false works and is cheaper. (c) Bond orders exist only in MoleculeIndex.bonds, not in the Uint8 grid, contradicting the 'one Uint8 grid is the single source of truth' decision; any 'rebuild index from grid' path (context restore, tests) silently resets double/triple bonds to single.
  - fix: Fix wording and flags in 6.6; use visible=false for the pick mesh; state that MoleculeIndex.bonds (orders) is authoritative alongside the grid and that index rebuilds must preserve the order map.
- **[minor] 5.1 challenge text**: C25 describes ibuprofen as bearing a '2-propanoic acid group' (not a valid name; it is a propanoic acid attached at C2). C09's instruction 'Turn it into ethyne' assumes the student is holding C08's ethene, but challenges are freely navigable.
  - fix: C25: 'a propanoic acid attached through its second carbon (2-arylpropanoic acid)'. C09: 'Build ethyne (or cycle ethene's bond to order 3)'.
