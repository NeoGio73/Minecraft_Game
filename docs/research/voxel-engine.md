== 1. Three.js r186 API notes that matter ==
- Import core from 'three'; addons from 'three/addons/<path>.js' (package.json exports "./addons/*" -> "./examples/jsm/*"; @types/three mirrors the same exports, so `import { PointerLockControls } from 'three/addons/controls/PointerLockControls.js'` type-checks). Geometry class is gone (removed from core in r125); only BufferGeometry exists.
- Renderer choice: use WebGLRenderer from 'three'. WebGPURenderer lives in the separate 'three/webgpu' entry (r171+), has an automatic WebGL2 fallback backend (and a `forceWebGL` option) but the unminified build is 2.2 MB vs 648 KB for three.module.js, drags in TSL/node materials, and headless Chromium in this container reports navigator.gpu === false, so smoke tests could not exercise it. Nothing in this game needs it.
- Color management defaults (source-verified): ColorManagement.enabled = true, workingColorSpace = LinearSRGBColorSpace, renderer.outputColorSpace = SRGBColorSpace. `new Color(0xrrggbb)`, setHex, setStyle assume sRGB input and convert to linear; `setRGB(r,g,b)` assumes linear unless you pass SRGBColorSpace. The GLSL chunk color_vertex.glsl does `vColor.rgb *= color` with NO conversion, so a `color` BufferAttribute must contain LINEAR values: build your palette as `const c = new Color(hex); palette.set([c.r, c.g, c.b], id*3)`. Canvas-generated color textures need `texture.colorSpace = SRGBColorSpace`.
- WebGLRenderer constructor defaults: antialias=false, powerPreference='default', failIfMajorPerformanceCaveat=false, pixel ratio 1, toneMapping=NoToneMapping. setSize floors width*pixelRatio.
- PointerLockControls r186 (extends the r169+ `Controls` base with `enabled`, `connect(el)`, `disconnect()`, `dispose()`): `new PointerLockControls(camera, domElement)`; `lock(unadjustedMovement=false)` calls `domElement.requestPointerLock({unadjustedMovement})` and IGNORES the returned promise (so rejections are unhandled); it listens on `domElement.ownerDocument` for mousemove/pointerlockchange/pointerlockerror; rotation = movementX/Y * 0.002 * pointerSpeed with YXZ Euler and pitch clamped by minPolarAngle(0)/maxPolarAngle(PI); events 'lock','unlock','change'; helpers getDirection(v), moveForward(d), moveRight(d); r120 removed getObject() (use .object). Recommendation: do not use it; write a ~40-line FirstPersonCamera (yaw/pitch, `camera.rotation.order='YXZ'`) that all three look modes feed, and call requestPointerLock yourself so you can catch the rejection.
- Frustum culling: Object3D.frustumCulled defaults true, and Frustum.intersectsObject only calls computeBoundingSphere() when geometry.boundingSphere === null. After every chunk rebuild call `geometry.computeBoundingSphere()` (or set `geometry.boundingSphere = null`) or chunks will pop in/out.
- Useful counters for the debug HUD/smoke test: renderer.info.render.calls and renderer.info.render.triangles (reset each frame).

== 2. Chunked world ==
Constants and layout:
```ts
export const CHUNK_W = 16, CHUNK_H = 32, CHUNK_D = 16;      // x, y, z
export const WORLD_CX = 8, WORLD_CZ = 8;                     // 128 x 32 x 128 cells
export type BlockId = number;                                 // Uint8: 0 = air
export const enum B { Air = 0, Floor = 1, Wall = 2, Glass = 3, /* atoms >= 16 */ C = 16, H, O, N, Cl, Br, S, F, I }
export const isAtom = (id: BlockId) => id >= 16;
export const isOpaque = (id: BlockId) => id !== B.Air && id !== B.Glass && !isAtom(id); // atoms are drawn separately at 0.62 scale, so terrain faces behind them must still be emitted
export const cidx = (x: number, y: number, z: number) => x + CHUNK_W * (z + CHUNK_D * y); // x fastest
export class Chunk { readonly data = new Uint8Array(CHUNK_W * CHUNK_H * CHUNK_D); dirty = true; mesh: Mesh | null = null; constructor(readonly cx: number, readonly cz: number) {} }
export class World {
  chunks: Chunk[]; // index cx + WORLD_CX*cz
  getBlock(x: number, y: number, z: number): BlockId;   // returns B.Air outside bounds (or B.Wall for y<0 if you want an unbreakable base)
  setBlock(x: number, y: number, z: number, id: BlockId): void; // marks chunk dirty, plus the neighbour chunk when x%16 in {0,15} or z%16 in {0,15}
}
```
Meshing: culled ("naive") meshing, not greedy. Why: the world is 524k cells but only ~16k non-air terrain cells (a 128x128 floor = 16,384 top faces = 32,768 triangles across 64 draw calls) plus atoms; a full-chunk culled pass is 8,192 cells x 6 neighbour lookups (< 1 ms in JS), so rebuilding on edit is trivially cheap. Greedy meshing (Lysenko: per axis d with u=(d+1)%3, v=(d+2)%3, build a 2-D mask from voxel[x] != voxel[x+q], grow width w then height h, emit quad, zero the mask) would cut the floor to a handful of quads but forces one colour per merged quad, breaks per-face vertex shading/AO variation and per-block labels, and is not needed at this scale. Integrated GPUs and Chromebooks are draw-call and fill bound, not bound by 50k triangles.
Mesher signature and buffers (pool one reusable buffer set, worst case per chunk = 8192 cells x 6 faces; use Uint32 indices because a checkerboard chunk exceeds 65,535 vertices; WebGL2 is guaranteed by Vite's baseline browser floor):
```ts
export interface MeshBuffers { pos: Float32Array; nor: Float32Array; col: Float32Array; idx: Uint32Array }
export const FACES: ReadonlyArray<{ dir: [number, number, number]; corners: [number, number, number][]; shade: number }>; // +y 1.0, -y 0.5, +x/-x 0.8, +z/-z 0.7; corners wound CCW seen from outside; indices per face [0,1,2, 0,2,3]
export function buildChunkMesh(get: (x: number, y: number, z: number) => BlockId, ox: number, oz: number, paletteLinear: Float32Array, out: MeshBuffers): number /* face count */
export function applyChunkMesh(chunk: Chunk, buf: MeshBuffers, faces: number, material: Material, scene: Scene): void
// applyChunkMesh: old geometry.dispose(); g = new BufferGeometry(); g.setAttribute('position', new BufferAttribute(buf.pos.slice(0, faces*12), 3)); same for normal (3) and color (3); g.setIndex(new BufferAttribute(buf.idx.slice(0, faces*6), 1)); g.computeBoundingSphere(); mesh.geometry = g (create mesh with matrixAutoUpdate=false at chunk origin on first use)
```
Face rule: for each non-air, non-atom cell, for each of 6 directions emit the face iff !isOpaque(get(neighbour)) (cross-chunk lookups go through World.getBlock). Colour per vertex = palette[id] * FACES[f].shade (cheap fake lighting even before real lights; skip vertex AO in v1). Material: one shared `new MeshLambertMaterial({ vertexColors: true })` (per-vertex lit, cheapest lit material); zero texture assets. Rebuild scheduler: each frame rebuild at most 2 dirty chunks (an edit touches 1, or 2-3 on borders). Slicing `.slice()` copies are fine at this size; do not bother with in-place attribute updates.
Texture atlas verdict: not needed for terrain; the only textures are runtime CanvasTextures for element letters (section 5).

== 3. Block picking (Amanatides-Woo DDA) ==
```ts
export interface VoxelHit { x: number; y: number; z: number; nx: number; ny: number; nz: number; t: number; id: BlockId }
export function raycastVoxels(ox: number, oy: number, oz: number, dx: number, dy: number, dz: number, maxDist: number, get: (x: number, y: number, z: number) => BlockId): VoxelHit | null
```
Direction must be unit length so t is world distance. Init: x=floor(ox) etc.; stepX = sign(dx) (0 if dx==0); tDeltaX = stepX ? Math.abs(1/dx) : Infinity; tMaxX = stepX>0 ? (x+1-ox)/dx : stepX<0 ? (x-ox)/dx : Infinity (same for y,z). Loop: if get(x,y,z) !== Air return {x,y,z,nx,ny,nz,t,id} (normal = -step of the axis crossed last; starting inside a block gives normal 0,0,0 — skip placement then); pick the smallest of tMaxX/tMaxY/tMaxZ, set t to it, advance that axis by its step, add its tDelta, record the normal; return null once t > maxDist (6). Camera ray: origin = camera.position, dir = camera.getWorldDirection(v) (crosshair at screen centre; no THREE.Raycaster needed for blocks). Placement cell = hit + normal; reject if outside world, non-air, or overlapping the player AABB. Keep a `BlockHighlight` (BoxGeometry(1.002) + LineSegments/EdgesGeometry) positioned at hit cell.

== 4. Player controller and input ==
```ts
export const PLAYER = { halfW: 0.3, height: 1.8, eye: 1.62, speed: 4.3, sprint: 6.5, jumpVel: 8.5, gravity: -28, maxFall: -40 };
export interface PlayerState { x: number; y: number; z: number; vx: number; vy: number; vz: number; yaw: number; pitch: number; onGround: boolean }
export function stepPlayer(p: PlayerState, input: FrameInput, dt: number, isSolid: (x: number, y: number, z: number) => boolean): void
```
Fixed timestep 1/60 with an accumulator, clamp real dt to 0.1 s. Move axis by axis (x, then z, then y): after moving one axis, iterate every cell overlapping the AABB [x-halfW, x+halfW] x [y, y+height] x [z-halfW, z+halfW] (floor(min) .. floor(max-1e-6)); if any isSolid, snap the box to that cell's face (moving +: pos = cellMin - halfW - 1e-4; moving -: pos = cellMax + halfW + 1e-4; for y use the feet/head), zero that velocity component, and set onGround when a -y move collided. Substep any axis delta larger than 0.5 blocks so a fast fall cannot tunnel. Jump only when onGround. Atom blocks count as solid full cells even though they render at 0.62 scale.
Input manager (canvas inside an LMS iframe):
```ts
export class InputManager { keys = new Set<string>(); lookDX = 0; lookDY = 0; mode: 'locked' | 'drag' | 'keys' = 'keys'; constructor(readonly canvas: HTMLCanvasElement) }
```
- canvas.tabIndex = 0 (MDN: tabindex=0 makes it sequentially focusable); `pointerdown` -> canvas.focus(); listen for keydown/keyup on the canvas itself and use `e.code` (KeyW/KeyA/KeyS/KeyD/Space/ArrowUp..., layout independent); `e.preventDefault()` for Space, Arrow*, and Tab-less keys you bind, so the D2L page/iframe does not scroll; `wheel` listener with {passive:false} + preventDefault for hotbar scrolling; `contextmenu` preventDefault. Clear the key set on canvas `blur`, window `blur` and `visibilitychange` (prevents stuck movement when the student clicks the D2L chrome).
- Pointer lock attempt (must run inside a click handler; transient activation required):
```ts
export async function tryPointerLock(el: HTMLElement): Promise<boolean> {
  if (!('requestPointerLock' in el)) return false;
  try { await (el as any).requestPointerLock({ unadjustedMovement: true }); }
  catch { try { await el.requestPointerLock(); } catch { return false; } }
  return document.pointerLockElement === el;   // promise may be undefined on older engines; pointerlockchange/pointerlockerror are the ground truth
}
```
MDN-verified constraints: sandboxed iframes block it unless `sandbox="allow-pointer-lock"`; only one iframe can hold lock; Escape exits (pointerlockchange fires) and an immediate re-request fails until a new engagement gesture; if you also call requestFullscreen(), call requestPointerLock() first. Chrome shipped then rolled back a pointer-lock permission prompt in 131 (likely).
- Fallbacks are mandatory (D2L may wrap uploaded HTML in a sandboxed iframe and the SCORM player is another frame): 'drag' mode = pointerdown(button 0) + setPointerCapture, pointermove deltas (`e.movementX/Y`, valid unlocked too) rotate the camera; pointerup within 250 ms and < 5 px = primary action (break); button 2 = place. 'keys' mode = ArrowLeft/Right yaw 2.5 rad/s, ArrowUp/Down pitch 1.5 rad/s, plus KeyQ = break and KeyE = place so the game is fully keyboard-operable. Touch: one-finger drag = look, tap = break, long-press = place (optional). Show the current mode and a "Click to capture mouse" hint in the HUD; on pointerlockerror switch to 'drag' silently.

== 5. Atoms and bonds ==
Recommended (cheapest that reads clearly): atoms are NOT part of the chunk mesh. Render each element as one InstancedMesh of BoxGeometry(0.62) with a runtime CanvasTexture per element (CPK background colour + contrasting letter baked into the texture; material colour white), lit by the same lights:
```ts
export const CPK_HEX: Record<Element, number> = { C: 0x3b3b3b, H: 0xf2f2f2, O: 0xe3242b, N: 0x2b5fe3, Cl: 0x1fd11f, Br: 0x9e1b1b, S: 0xf2e21f, F: 0x90e050, I: 0x940094 };
export function makeElementTexture(symbol: string, bgHex: number, fg: 'black' | 'white', size = 128): CanvasTexture // draws all 6 faces identical: fill bg, bold sans letter ~70% of size, 6px darker border; texture.colorSpace = SRGBColorSpace; generateMipmaps = true
export class AtomRenderer { private meshes: Map<Element, InstancedMesh>; constructor(scene: Scene, maxPerElement = 1024); rebuild(atoms: Iterable<AtomRef>): void /* setMatrixAt per instance, mesh.count = n, instanceMatrix.needsUpdate = true */ }
```
Because texture x material colour is multiplicative, baking the colour into the texture is what keeps white letters on dark carbon readable (a white-letter alpha map times dark grey would vanish). Sprites are rejected (they would sit inside the cube or float above it); HUD-only listing is rejected for clarity but keep a colour legend in the HUD for colour-blind students. The 0.38 gap between adjacent 0.62 cubes is exactly where bonds live.
Bonds: one InstancedMesh (BoxGeometry(0.11, 0.11, 1.0) or CylinderGeometry(0.06,0.06,1,6), MeshLambertMaterial grey 0x9a9a9a), one instance per bar: midpoint of the two cell centres, quaternion `setFromUnitVectors(+Z, axisDir)`, length 1.0 (ends hide inside the cubes); bond order 2 = two bars offset ±0.13 along a perpendicular (use +Y for x/z bonds, +X for y bonds), order 3 = 0, ±0.17; bars width 0.08 for orders 2-3. Data model derived from the Uint8Array grid so there is one source of truth:
```ts
export type CellKey = number; export const key = (x: number, y: number, z: number) => x | (z << 7) | (y << 14);
export interface AtomRef { key: CellKey; el: Element; x: number; y: number; z: number }
export class MoleculeIndex { atoms = new Map<CellKey, AtomRef>(); bonds = new Map<number, 1 | 2 | 3>(); /* pairKey = min(k1,k2)*2**21 + max */ rebuildFromWorld(w: World): void; neighbours(k: CellKey): AtomRef[] /* 6 face neighbours only in v1 */ }
export class BondRenderer { mesh: InstancedMesh; constructor(scene: Scene, maxBars = 4096); update(m: MoleculeIndex): void }
```
Auto-create single bonds when two atoms become face-adjacent; a "bond tool" cycles order 1->2->3->1 via `new Raycaster().setFromCamera(new Vector2(0,0), camera).intersectObject(bondRenderer.mesh)` -> `hit.instanceId` -> bar-to-bond lookup table (InstancedMesh raycast is supported; likely). Draw-call budget: 64 terrain + <=9 atoms + 1 bonds + highlight/HUD = under 80 calls.

== 6. Performance and quality knobs ==
- `new WebGLRenderer({ canvas, antialias: !lowGfx, powerPreference: 'high-performance' })`; `renderer.setPixelRatio(Math.min(devicePixelRatio, lowGfx ? 1 : 1.5))`; resize with ResizeObserver on the canvas's parent (the D2L iframe viewport), not window.innerWidth.
- lowGfx heuristic at startup (antialias needs renderer creation): `matchMedia('(prefers-reduced-motion: reduce)').matches` || navigator.hardwareConcurrency <= 4 || /CrOS/.test(navigator.userAgent) || unmasked renderer string (WEBGL_debug_renderer_info, still exposed in Chromium 141) contains 'SwiftShader' || 'llvmpipe'; then after 120 frames if mean frame time > 22 ms drop pixel ratio to 1. Persist a user "Low graphics" toggle in localStorage.
- Lighting: HemisphereLight(0xdfe9ff, 0x6b6b6b, 1.0) + DirectionalLight(0xffffff, 1.2) at (0.5,1,0.3), shadows off, MeshLambertMaterial everywhere; scene.fog = new Fog(clearColor, 40, 110) with camera.far = 120 so distant chunks blend out; keep scene.background === fog colour.
- Frustum culling is automatic per chunk mesh (see bounding-sphere note). Skip rendering (return from the RAF loop) when document.hidden or an IntersectionObserver reports the canvas off-screen in the LMS page; RAF already throttles in background tabs.
- Reduced motion toggle: no head bob, no camera easing, no particle/flash effects, instant HUD transitions.
- Handle `webglcontextlost` (preventDefault, pause) / `webglcontextrestored` (three re-uploads resources; mark all chunks dirty to be safe) — integrated GPUs on Chromebooks lose contexts under memory pressure. Always dispose replaced geometries.

## Recommendations

- Use WebGLRenderer from 'three' (not three/webgpu): ~650 KB unminified core vs 2.2 MB, works on every Chromebook/integrated GPU, and is the only path the headless smoke test can exercise (navigator.gpu is false in headless Chromium here).
- World = 8x8 chunks of 16x16x32 stored as one Uint8Array per chunk (index x + 16*(z + 16*y)); atoms occupy cells as BlockIds >= 16 so collision, DDA picking and chemistry all read one source of truth; World.setBlock marks the chunk (and border neighbours) dirty and a scheduler rebuilds <= 2 chunks per frame.
- Mesh terrain with a culled face mesher (emit a face iff the neighbour is not opaque; atoms and glass count as non-opaque), one BufferGeometry per chunk with position/normal/color attributes and Uint32 indices, shared MeshLambertMaterial({vertexColors:true}); skip greedy meshing (per-quad colour limits, no measurable gain at ~16k terrain blocks). Always call geometry.computeBoundingSphere() and dispose the replaced geometry.
- Vertex colours and any Color-derived data must be linear: build the palette with `new Color(hex)` (auto sRGB->linear) and copy .r/.g/.b into the attribute; set colorSpace = SRGBColorSpace on runtime CanvasTextures; leave renderer.outputColorSpace at its SRGB default.
- Block picking: implement raycastVoxels(ox,oy,oz,dx,dy,dz,maxDist=6,get) with Amanatides-Woo (step/tMax/tDelta, Infinity for zero components) returning cell + face normal; place at hit+normal after bounds/air/player-AABB checks. No THREE.Raycaster for blocks; use Raycaster only against the bond InstancedMesh.
- Player: fixed 60 Hz step, per-axis AABB (0.6 x 1.8, eye 1.62) sweep against the voxel grid with sub-stepping > 0.5 block, gravity ~-28, jump only when onGround.
- Input: canvas.tabIndex=0, focus on pointerdown, keydown/keyup on the canvas using e.code, preventDefault on Space/Arrow keys and wheel (passive:false), clear keys on blur/visibilitychange. Implement a three-mode look controller (pointer lock -> drag-to-look -> arrow-key look) with your own yaw/pitch camera; call requestPointerLock yourself inside the click handler, await/catch it, retry without unadjustedMovement, and treat pointerlockchange/pointerlockerror as ground truth. Provide KeyQ/KeyE (break/place) so the game is playable keyboard-only inside a sandboxed D2L iframe.
- Atoms: per-element InstancedMesh of BoxGeometry(0.62) with a runtime CanvasTexture that bakes the CPK colour plus a contrasting letter (white on C/N/Br/I, black on H/O/S/F/Cl); bonds: one InstancedMesh of thin boxes (0.11) between adjacent cell centres, 1/2/3 parallel bars offset ±0.13 / 0,±0.17 for bond order; auto single-bond on adjacency, bond tool cycles order via Raycaster instanceId. Keep a colour legend in the HUD.
- Quality knobs: antialias off when lowGfx (decided at renderer creation from prefers-reduced-motion, hardwareConcurrency<=4, CrOS UA, SwiftShader/llvmpipe renderer string, then a 120-frame timing check), pixel ratio cap 1.5 (1.0 lowGfx), hemisphere + directional light with shadows off, Fog(clear colour, 40, 110) with camera.far 120, pause the loop when document.hidden or the canvas is off-screen, honour a persisted 'Low graphics / reduced motion' toggle, handle webglcontextlost/restored.
- Keep vite.config.ts base './', single bundle (no dynamic imports), chunkSizeWarningLimit ~1500, sourcemap off; upload the whole dist/ folder to D2L each release because asset names are hashed.
- Unit-test pure modules with vitest (mesher face counts, DDA hits/normals, AABB collision, MoleculeIndex); keep three out of those modules so they run in the node environment.
- scripts/smoke.mjs must launch playwright-core with an explicit executablePath (CHROME_PATH env or a glob over $PLAYWRIGHT_BROWSERS_PATH/chromium-*/chrome-linux*/chrome; /opt/pw-browsers/chromium-1194/chrome-linux/chrome here), serve dist/ under a nested path to prove the relative base, fail on pageerror/console errors, wait for window.__orgocraft.frames > 10 && triangles > 0, and save a screenshot to test-results/.
- GitHub Actions: checkout@v7 (or v4), setup-node@v7 node 22 with npm cache, npm ci, typecheck, vitest, build, package:d2l/package:scorm, upload-artifact@v7 of release/*.zip (if-no-files-found: error); optionally upload the unzipped SCORM folder as a second artifact so GitHub's download is a directly importable SCORM zip; in CI install the full `playwright` package pinned to 1.63.0 and run `npx playwright install --with-deps chromium` for the smoke job.

## Risks

- Pointer lock will often be unavailable inside D2L: uploaded HTML may be wrapped in a sandboxed iframe (needs allow-pointer-lock), the SCORM player is another frame, only one frame can lock at a time, and after Escape an immediate re-lock fails; the drag-to-look and arrow-key fallbacks are therefore the primary path for many students, not an edge case. requestFullscreen() may likewise be blocked without allowfullscreen on the D2L iframe; catch and continue.
- D2L iframe behaviour (sandbox tokens, MIME type served for .js module files, fixed iframe height, whether scripts are allowed at all for uploaded HTML) could not be verified from primary D2L documentation (hosts blocked); test an actual upload early, and design the canvas to fill the iframe viewport (ResizeObserver) rather than window dimensions.
- Local Playwright toolchain mismatch: playwright-core 1.63.0 looks for chromium-1243 but only chromium-1194 (Chromium 141) is installed; any smoke script that calls chromium.launch() without executablePath fails, and driving a newer/older Chromium through an unmatched playwright-core is unsupported (it worked in this session's probe).
- Writing sRGB hex components straight into the vertex colour attribute or forgetting texture.colorSpace = SRGBColorSpace produces washed-out CPK colours; three's colour pipeline is linear-working / sRGB-output by default.
- Forgetting computeBoundingSphere() after rebuilding a chunk geometry, or using Uint16 indices for a chunk that can exceed 65,535 vertices, causes chunks to vanish under frustum culling or overflow silently.
- Integrated GPUs / Chromebooks can lose the WebGL context under memory pressure and may fall back to software rendering (SwiftShader) where even 50k triangles at DPR 2 is slow; handle webglcontextlost/restored and detect software renderers to force low graphics.
- Chrome experimented with a pointer-lock permission prompt in 131 (later reverted, per secondary sources); browser policy here can change again, another reason fallbacks must stay first-class.
- Hashed Vite asset names change every build, so an instructor who re-uploads only index.html to D2L gets a broken page; document 'upload the whole dist folder' or switch to stable names and accept cache-busting responsibility.
- Keyboard focus: the canvas receives no key events until the student clicks it, Space/Arrow keys scroll the surrounding D2L page unless preventDefault is called, and keys get stuck when focus leaves the iframe mid-press unless the key set is cleared on blur.
- Release dates/tags for actions/checkout and actions/upload-artifact v7 came from GitHub HTML page summaries with inconsistent year reporting; pin what the workflow run actually resolves (v4/v5 majors remain valid fallbacks).
