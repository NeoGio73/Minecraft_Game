# Research: d2l-hosting

_Source: workflow agent `research:d2l-hosting`._

## Summary

Hosting the Vite/Three.js voxel game as plain files in a D2L Brightspace course is workable and is the lower-risk path versus SCORM for a no-backend app. Workflow: Course Admin > Manage Files > Upload the zip > Unzip (background job) > tick index.html > "Add Content Topics" > pick module/title. Files land under the course's enforced content root and are served same-origin at https://<lms-host>/content/enforced/<orgUnitId>-<orgUnitCode>/<folder>/index.html?d2lSessionVal=...&ou=<orgUnitId>. The classic content viewer renders an HTML topic inside an <iframe class="d2l-iframe d2l-iframe-fit-user-content" ... allowfullscreen="" allow="microphone *; camera *"> with NO sandbox attribute and auto-resizes the iframe height to the inner document (default 580px). Consequences: (a) Vite must build with base './' and never use root-absolute runtime URLs; ES modules work because the iframe is same-origin (D2L serving .js with a JS MIME type is likely but could not be read from a primary source); (b) Pointer Lock and Fullscreen are permitted in principle (no sandbox flag; allowfullscreen present; "pointer-lock" is not a Permissions-Policy feature so no allow= is needed), but both require a user gesture and can still fail (admin-enabled iframe sandboxing exists as a D2L feature, Esc-then-immediate-relock fails), so implement drag-to-look + keyboard-look fallbacks and an "Open in new tab" link; (c) 100vh layouts collapse inside the auto-height iframe, so size the stage by width/aspect-ratio; (d) Space/Arrow keys must be preventDefault-ed inside the iframe document with a focusable canvas (tabindex=0, focus on pointerdown). Gotchas: never click "Edit HTML" on the topic (Brightspace Editor strips scripts); re-uploads with the same filename can serve stale copies (deploy to versioned folders); http:// subresources are blocked as mixed content; externally hosted (e.g., GitHub Pages) embeds go through "Create a Link" (embedded unless "Open as External Resource") or Insert Stuff > Enter Embed Code, where non-Trusted-Sites embeds prompt users unless an admin allowlists the domain. D2L's restricted-extension list blocks server-executable types (ASP/ASHX/EXE/DLL/CONFIG/etc.) but not .js/.json/.wasm/.glb/.css/.html/.map; default max upload is 2 GB per file. Accessibility: public colleges are under the DOJ Title II rule (28 CFR 35.200) requiring WCAG 2.1 AA for LMS course content (original dates 2026/2027; DOJ's April 2026 interim final rule reportedly pushed them to April 26, 2027 / April 26, 2028). The game should be fully keyboard-operable (2.1.1: mouse-look is path-based input but turning/selection are not, so keyboard turning is required), single-key shortcuts only active when the canvas has focus (2.1.4), no keyboard trap with documented exit (2.1.2), a role="status" aria-live region plus a structured text description of the scene/molecule (1.1.1, 4.1.3), element colour always paired with symbol labels (1.4.1), 4.5:1 HUD text and 3:1 UI/crosshair contrast (1.4.3, 1.4.11), no flashing above 3 Hz (2.3.1), pausable/reduced motion (2.2.2), no hard time limits (2.2.1), visible focus (2.4.7), and all menus/quizzes built in the DOM rather than drawn on canvas.

## Recommendations

- Vite config for the D2L build: base: './' (mandatory), keep build.assetsDir 'assets', and never reference runtime assets with root-absolute strings (e.g. TextureLoader.load('/textures/x.png')); use new URL('./textures/x.png', import.meta.url) or import.meta.env.BASE_URL + 'textures/x.png' so paths resolve under /content/enforced/<ou>-<code>/<folder>/. Avoid public/ assets referenced by absolute path or run a post-build check that dist/ contains no '"/assets/' or 'src="/' occurrences.
- Do not depend on WebAssembly.instantiateStreaming or on any specific MIME type for .wasm/.glb/.json: fetch bytes (arraybuffer) and instantiate; three.js DRACOLoader/GLTFLoader already do this. Ship no files with restricted extensions (.sh, .config, .exe, .dll, .bat, .jar, .cmd, .ps1) inside the zip; .js/.css/.json/.wasm/.glb/.png/.webp/.map are fine.
- Packaging and instructor steps to document: zip the CONTENTS of dist/ into a versioned folder (e.g. orgo-voxel-v1/index.html, orgo-voxel-v1/assets/...); Course Admin > Manage Files > Upload (<= 2 GB) > open the zip's action menu > Unzip (wait for the background-job notification) > tick orgo-voxel-v1/index.html > Add Content Topics > choose module and title. Tell the instructor to NEVER use 'Edit HTML' on the topic (the Brightspace Editor strips scripts) and to release updates as a new versioned folder then 'Change File' on the topic (avoids stale index.html caching while hashed asset names handle the rest).
- Layout for the auto-height iframe: do not use 100vh/100dvh for the stage. Use a width-driven box (width:100%; aspect-ratio:16/9; min-height:480px) with html/body overflow:hidden, set a real <title> (D2L reads it), and on fullscreen (document.fullscreenElement) switch the stage to 100% of the fullscreen element. Detect framing with window.self !== window.top and show a toolbar with 'Open in new tab' (a.href = location.href, target=_blank, rel=noopener; same-origin so the D2L session cookie carries over) and 'Fullscreen' (container.requestFullscreen() inside the click handler, hidden if !document.fullscreenEnabled).
- Mouse-look with graceful degradation: on canvas click call canvas.requestPointerLock({unadjustedMovement:true}).catch(() => canvas.requestPointerLock()); treat promise rejection, the 'pointerlockerror' event, or document.pointerLockElement !== canvas after ~150 ms as failure and switch to drag-to-look (pointerdown -> setPointerCapture -> pointermove deltas -> pointerup, with a sensitivity slider and invert-Y option). Always provide keyboard look (arrow keys or Q/E, with adjustable turn speed) and touch drag, so play never depends on pointer lock. After the user presses Esc, do not auto-relock; wait for the next click (immediate relock is rejected by spec).
- Keyboard handling inside the iframe document: give the canvas tabindex="0", an accessible name (aria-label) and call canvas.focus() on pointerdown; register keydown/keyup on window and, only when document.activeElement is the canvas or pointer lock is active, call preventDefault() for ' ', ArrowUp/Down/Left/Right, PageUp/PageDown, Home/End (never for Tab, Escape, F-keys or when a DOM input/dialog has focus). Make Esc open the pause menu (it also releases pointer lock) and let Tab leave the canvas normally; state the exit keys in the on-screen help to satisfy WCAG 2.1.2 and make WASD-style single-key shortcuts active only while the canvas has focus (2.1.4), with a remap screen.
- Build all menus, HUD text, hotbar, challenge prompts and quizzes as DOM elements overlaid on the canvas (not painted in WebGL) so they are focusable, labelled and contrast-checked; put game state in <div role="status" aria-live="polite" aria-atomic="true"> (selected element/bond tool, current molecule name/formula, challenge result) throttled to at most one update per second, errors in role="alert", and keep a hidden but screen-reader-readable structured description of the scene (nearby atoms, bonds, current molecule as IUPAC name/SMILES) updated on change to satisfy 1.1.1/4.1.3.
- Visual/motion rules for WCAG 2.1 AA: pair every colour code with a text/shape cue (element symbol labels on blocks, bond-order glyphs, icons plus text for states); HUD text 4.5:1 and crosshair/UI components 3:1 on a translucent dark backing; no flashing above 3 Hz (use fades, not strobes, for reaction effects); honour prefers-reduced-motion (disable head-bob/FOV kicks) and provide a Pause that freezes the world and ambient animation; no timed challenges, or make the timer optional/extendable; visible focus ring on DOM controls and on the canvas when focused.
- Alternative hosting path to keep in the design (optional): host the same dist/ on GitHub Pages or a campus static host and add it in D2L via Content > Create a Link (leave 'Open as External Resource' unchecked to embed, or check it to open in a new tab) or Insert Stuff > Enter Embed Code with allowfullscreen; note the campus admin may need to add the domain under Admin Tools > Trusted Sites to suppress the 'allow this content?' prompt, and all subresources must be https to avoid mixed-content blocking. Cross-origin framing still permits pointer lock (not sandboxed) and fullscreen only if the D2L-generated iframe carries allowfullscreen.
- Add a D2L smoke-test checklist before hand-off: (1) module script loads with no MIME/404 errors in DevTools under /content/enforced/; (2) click locks the pointer and Esc releases it; drag-look works when lock fails; (3) Fullscreen button works from inside the viewer; (4) Space/arrows do not scroll the D2L page; (5) whole game completable with keyboard only; (6) NVDA/VoiceOver announces the status region; (7) the iframe height is sensible (no 580px squash) and the page has no scroll trap; (8) re-upload to a new versioned folder shows the new build without cache clearing.

## Risks

- Primary D2L documentation (community.d2l.com), MDN HTML pages, ADA.gov and most institutional help sites were blocked by this environment's egress proxy; D2L workflow, size-limit, Trusted Sites, caching and editor-stripping facts rest on search snippets and saved page copies and should be spot-checked by the instructor on their instance.
- Brightspace instances differ by admin configuration: an org-level 'secure iframe sandbox' option for HTML files exists per institutional docs; if the instructor's campus enables a real HTML sandbox attribute without allow-pointer-lock/allow-scripts, pointer lock (or even scripts) would fail, so the fallback controls and the 'Open in new tab' link must not be optional.
- The New Content Experience (Lessons) viewer was not verified; if the course uses Lessons, the iframe attributes and height behaviour may differ from the classic viewer analysed here (re-test pointer lock, fullscreen and layout there).
- D2L's auto-height iframe (default 580px, overflow hidden) can squash or clip a viewport-sized canvas and can cause resize feedback loops if the game resizes its stage based on inner height; size by width/aspect ratio and cap resize handling.
- Stale index.html caching after re-uploads with the same filename is reported by instructors; since Vite hashes asset names but not index.html, a cached index.html referencing deleted hashed assets yields a blank game unless releases go to new folders or students hard-refresh.
- Pointer lock UX in an LMS is fragile: the lock is lost on Esc, on tab switch, and cannot be re-acquired immediately after the user presses Esc; students unfamiliar with the mechanic may think the game froze, so on-screen 'click to look / Esc to release' prompts are needed.
- Accessibility exposure is real for public colleges: 28 CFR 35.200 requires WCAG 2.1 AA for course content provided through the LMS (dates 2026/2027, reportedly extended to 2027/2028 by the April 2026 interim final rule, which could not be read in primary form). A 3D WebGL game is inherently hard to make fully conformant; provide an equivalent non-3D path (DOM-based molecule builder/quiz) or the institution may need an accommodation plan.
- Chromium keyboard-scroll bubbling from a non-scrollable iframe to the parent D2L page was only confirmed through forum reports; regardless, preventDefault on Space/arrow keys inside the game document is required and must be scoped so it does not break D2L's own controls when the canvas is not focused.
- Whether D2L's unzip step rejects or silently drops restricted-extension files inside a zip was not verified; keep the build output free of any such extensions to avoid partial deployments.
